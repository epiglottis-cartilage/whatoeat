# 研究计划与后续实施路线

记录日期：2026-09-22。本计划针对本地优先 Dioxus 桌面/安卓应用。P0–P2 已完成，5 张原图/视频帧已存档。用户随后授权编写 UI，P4–P7 首版结构/实现已完成，见[实施蓝图](implementation.md)及[验收记录](implementation-validation.md)。P3 原作动效取证保留待办，本版改用明确标注的本应用自定过渡；不宣称完成忠实复现。

## 第一轮研究交付边界（已完成，保留历史）

- 保留已有五套配色，四套阵营名改为独立的配色名称；不迁移历史设置 key。
- 收集传统主界面、生息演算和一组集成战略对照图，归档可核验的来源信息。
- 分析空间骨架、形状、颜色职责、倾斜/透视、文字图层和状态层级。
- 区分静态证据与动效假设；规划后续一次只完成一套界面的步骤。
- 使用 jj 保存项目基线与本轮研究变化。
- 不修改业务算法、数据、CSS 规则、动画或当前页面布局。

## 逐套推进顺序

**第一套：传统主界面。** 先验证重心分区、主视觉与操作面板的重叠关系，以及层次化文字。把背景装饰和点击目标分离，再决定是否使用透视式面板。

**第二套：生息演算。** 先验证总览/资源/区域信息的层级如何映射到候选、饮食时间和菜单状态。保留一次只推荐一个候选的核心产品约束，不为模仿地图而制造多候选游戏流程。

**第三套：集成战略。** 用作节点、路径、可达/不可达状态的对照。它可能更适合历史页或过程展示，不预设必须成为首页主题。

实施时先约定共用组件和布局接口，再在独立主题文件中实现几何与层次，并分别检查截图及完整状态。当前没有原作运动参数，使用自主设计的短过渡；后续补证不能绕过减少动态效果要求。

## 每套未来实现的工作包

1. **证据补齐**：至少主状态、选中/按下、进入/退出各一份；来源不同时说明差异。
2. **映射草案**：对照本应用候选卡、吃/不吃、历史、菜单、复制与合并、全局通知、主题选择。
3. **静态骨架**：先检查排版、遮挡和阅读顺序；不靠动画掩盖布局问题。
4. **组件状态**：默认/悬停/键盘焦点/按下/禁用/加载/错误/空状态。
5. **运动设计**：分别写明对象、触发、起止状态、相对顺序；实测参考值与应用自定值分栏。
6. **平台验证**：桌面 WebView、安卓 WebView、触摸/鼠标/键盘；性能和可读性优先。
7. **独立 jj 变化**：保存研究、静态实现、动效、验证的边界，留出可回退点。

## 响应式与功能门槛

- 检查 360、390、760、1060 CSS px；横屏参考不能直接压缩到竖屏。
- 固定底部菜单始终可用，滚动到底部时页脚完整出现于其上方。
- 候选名称长短变化、空菜单、全部拒绝、记录成功/撤销均可读。
- 通知不推动布局，不遮挡关键操作到无法完成流程。
- 形状变换不能缩小有效点击区域；文本不因拟真透视而难以阅读。
- 键盘焦点可见，色彩之外还有状态提示，启用 `prefers-reduced-motion` 时流程完整。
- 沿用当前主题持久化、分钟级记录、增量覆盖与撤销语义。
- 先验证一个页面/状态，再扩大范围；不为了视觉重做引入新的数据模型或平台框架。

## jj 工作方式

当前项目已是 jj 仓库，不再另建 Git 分支。使用稳定 change ID 作为研究锚点；commit ID 会随后续编辑而变化。

```sh
jj status
jj log -r '@ | @-'
jj diff --stat
# 完成一个可独立审阅的工作包后：
jj describe -m '描述本工作包'
jj new -m '下一工作包'
# 追溯本地操作：
jj op log
```

本轮不推送远端。不要对用户已有变化执行整体 restore；未来回退先明确目标 change 与文件范围。设计文档中的待办状态随每次实现更新，避免只留一份很快失效的长计划。
