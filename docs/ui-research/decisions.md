# 决策与未决问题

## 已明确的边界

| 编号 | 决策 | 原因/约束 |
| --- | --- | --- |
| D-01 | 配色与界面体系分开命名 | 阵营色不能替代真实 UI 的几何、排版和运动分析 |
| D-02 | 五套现有样式保留，旧持久化 key 不改 | 不打断用户已有选择，也不把本轮研究变成兼容迁移 |
| D-03 | 首轮只研究；用户随后授权开始 UI 实施 | 保留最初研究边界及后续授权顺序；当前实现见 implementation.md |
| D-04 | 原图、观察、推断、迁移假设分开保存 | 保证后续实现可以追溯依据，不把估计当原作参数 |
| D-05 | 横屏参考需单独做竖屏适配设计 | 原样缩放会损坏文字与触摸目标，不能等到实现末尾处理 |
| D-06 | 保留单候选、直接记餐、撤销、分钟去重等业务语义 | 视觉重设计不隐含改造产品与学习算法 |
| D-07 | 用 jj 记录基线与独立工作包 | 可审阅、可追溯；本轮不推送远端 |
| D-08 | 图像仅作为研究引用 | 不把参考截图或来源站点作为产品资源及运行时依赖 |
| D-09 | 当前使用原创 SVG、CSS 几何层和自定短过渡 | 未证实原作动画，不声称复刻时长、视差或渲染技术；支持减少动态效果 |
| D-10 | 三套界面共用业务组件和本地主题偏好 | 避免复制推荐/记录逻辑；已有配色继续保留，新 key 独立存储 |

## 等待证据或下一阶段决定

- 各界面选中、返回、页间转场的真实顺序和时长；没有观察到的行为不填精确毫秒。
- 传统主界面背景与前景是否存在输入驱动视差，以及具体版本差异。
- 生息演算日开始总览与区域地图之间的真实操作和转场；活动入口、存档选择还需补证。当前两帧前景 UI 基本正置，不能由物品插画的斜面推导整页透视。
- 手机竖屏首版已重排并检查四种宽度；安卓实际设备的键盘、触摸与系统栏仍需验收。
- 菜单、历史、复制与合并已沿用各主题形状语言；后续依据真实使用反馈迭代密度与信息优先级。
- 首版主视觉选择原创场景/餐碗图形，不使用角色立绘。是否需要更丰富的食物插画另行决定。
- 动态装饰的成本、低性能设备策略和减少动态效果分支，需在实际实现阶段测量。

## 阅读静态图时的限制

平行四边形可能来自剪切，也可能只是切角轮廓；四边不平行的面板只说明透视式表现，不能证明具体的 CSS `perspective`、3D 矩阵或原作渲染方式。文字倾斜与面板倾斜应分别观察。阴影/半透明/遮挡能支持层次判断，不能独自证明随指针移动的视差。

颜色受背景、压缩、显示及透明叠加影响。未经过原图像素采样的色值只记录为“深灰/冷白/黄色强调”等类别；即便采样，也不是游戏设计 token 的直接证明。
