| 维度 | 传统主界面 | 生息演算「沙洲遗闻」 | 集成战略「傀影与猩红孤钻」 |
| --- | --- | --- | --- |

| 形状词汇 | 大四边形板、圆环身份、跨边角标、细强调条 | 圆角深色总览板、胶囊按钮；地图用小方节点、圆形地标与日计数器 | 横向矩形节点、窄黑标签、曲线箭头，外框以直角为主 |

| 透视在哪里 | 部分四边形对边不平行，有透视式表现；无法确认原作渲染技术 | 地图地貌和物品图标有体积线索；没有证据要求整体 UI 做 3D 旋转 | 背景建筑有纵深，前景路线与工具栏保持二维正视 |
| 颜色职责 | 白/灰承载主内容，青蓝强调部分功能，橙色落在细条和通知 | 沙土/棕褐提供环境，深色容器承载信息，黄用于当前行动和日期；地图也有红/蓝状态 | 暗背景衬托白色路线与图标，黄/青区分近端节点，红色用于退出入口 |
| 文字组织 | 大宋体式功能名、无衬线数字、小副说明、淡水印形成多层 | 大数字与短状态词；地图中文地名在前，大字距低对比英文在后；总览正文更实用 | 节点名称与窄英文类别组合；顶部数值突出，边缘标签次之 |
| 层次形成 | 场景、人物、悬浮板、板内淡图形、正文、外置标记相互遮挡 | 总览以暗背景衬信息板；地图以地貌、雾、地名、路径和边缘工具形成层次 | 虚化背景、清晰连接线与节点、上下栏形成前后关系 |
| 留白用途 | 人物轮廓与板群之间形成呼吸空间 | 总览把当前产出与后勤分开；地图留白用于地点关系 | 节点间距离直接承载分支与路径信息 |

## 对后续设计有约束力的发现

1. **不存在可覆盖所有样本的统一倾角。** 主界面的投影关系、区域地图的正置工具、路线图的平面节点应该分别研究。只给外壳加斜切会同时丢失三者的差异。
2. **结构辨识早于色板。** 去掉强调色，主界面的不等大板群、区域地图的边缘状态与中心空间、路线图的连接关系仍然不同。未来线框应先在灰阶下表达这种差异。
3. **文字不是单一字体和字号的排列。** 主标题、数值、副说明、背景字样承担不同职责。尤其要把可读正文与装饰性大字分开；后者不能挤走菜名和操作。
4. **透视是一种可见关系，不是现成技术选型。** 四角关系可支持投影式表现，却不直接要求 CSS 3D、WebGL 或任何特定实现。先确定需要哪种画面关系，再做平台可行性验证。
5. **留白有时是信息。** 路径和地图需要表达距离/连接；填满每一块空白可能破坏原本的结构。现有菜单的高效列表与地图式视图不能简单套用相同密度。
6. **动效仍需独立取证。** 静态的光晕、雾和阴影不能证明它们在运动；即使来源是视频，也不能把抽帧观察写成已经量化的动画规则。

## 迁移到本应用的候选方向（尚未设计或实施）

| 本应用对象 | 可以检验的方向 | 必须保留的约束 | 进入实施前需要的产物 |
| --- | --- | --- | --- |
| 当前推荐与吃/不吃 | 传统主界面的主次分区：一个明显的决策面板，其余入口降低重量 | 一次一个候选；吃即记餐；长菜名完整可读 | 桌面/竖屏线框、正常/全部拒绝/空菜单状态 |
| 本日记录与推荐依据 | 生息总览的当前产出、后勤和日状态分组关系 | 只展示有实际含义的数据，不为了模仿增加虚假资源 | 字段层级、展开与收起规则、数据缺失状态 |
| 饮食历史 | 集成战略的节点、路径、窄信息条可用于时间关系 | 分钟级记录、修改与撤销保持清楚；不新增分支选择 | 时间线草图与长列表滚动验证 |
| 我的菜单 | 研究资源栏/节点的紧凑元信息分组 | 改名、启停、删除易发现；桌面空白与手机堆叠分别处理 | 短/长名称、少量/大量项的排版样本 |
| 全局导航与提示 | 借鉴边缘工具与前景通知的层次区分 | 底部菜单固定；页脚在其上方；提示不推移布局 | 覆盖关系图、触摸目标、键盘焦点与安全区方案 |
| 主题选择 | 现有配色与未来完整界面体系清晰区分 | 保留现有选择与本地持久化 | 命名/选择规则；不提前决定是否需要新存储字段 |

这些方向只说明哪些结构值得试验，不要求每个页面都变成游戏地图。是否保留人物式主视觉、是否把集成战略发展成完整主题，仍是下一阶段的设计判断。
