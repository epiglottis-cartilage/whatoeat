## 配色与完整界面分开

主题下拉框继续直接切换，保留现有五套配色及持久化 key；增加三个具有独立结构的界面主题。沿用同一个本地偏好，不引入同步或新的数据存储方式。

| 类型 | 选择 key | 设计职责 |
| --- | --- | --- |
| 既有配色 | `poster`、`rhodes`、`rhine`、`penguin`、`kazimierz` | 保留原味海报、冰蓝终端、苔绿纸页、赤橙速递、鎏金夜幕的已有样式 |
| 主界面方向 | `control` | 不等大面板与重心分区，淡文字层与正文层分离，局部透视式装饰 |
| 生息演算方向 | `reclamation` | 边缘状态、中心信息场、圆形日状态与圆角信息容器 |
| 集成战略方向 | `expedition` | 清晰的平面节点与连接线，前景路径和背景纵深分离 |

三个界面共用业务状态和操作。布局差异由主题专属结构、附加信息层和样式表达，不能复制三套记录、导入或推荐逻辑。所有额外信息来自真实菜单和饮食记录，装饰图层不冒充可操作数据。

## 响应式规则

- **1060 px**：表达桌面面板层级与空间关系；正文和点击目标保持正常阅读坐标，倾斜/透视只用于不损害阅读的图形层。
- **760 px**：作为底部导航模式的上界，检查导航位置、状态栏折行和完整页面滚动。
- **390 px**：将横向面板关系重组为竖向阅读顺序，不整体缩小桌面界面；菜名、解释、吃/不吃优先。
- **360 px**：覆盖窄屏、长菜名、长菜单、历史列表、表单与通知，不能靠隐藏核心内容或制造横向滚动通过。

三个完整界面主题的底部菜单在桌面和移动布局均固定于视口底部，旧配色保留原先的桌面侧栏／移动底栏布局。内容预留菜单和安全区空间；页脚随内容滚动，抵达页面末尾时完整出现在菜单上方。装饰不接收指针事件，也不遮住焦点轮廓。

## 状态与动效边界

推荐页需要验证正常候选、菜单为空、全部拒绝、已接受、候选过期、加载、长名称和提交中。菜单、历史、复制页使用相同业务状态来源与全局通知出口，避免新增一套临时通知布局。

目前没有量化原作转场、输入视差或选中动画。本轮只允许本应用自定的短入场、状态反馈和悬停/按下过渡；这些动效不是对原作时间、缓动或逐帧运动的复现。不根据单张截图编造循环雷达、持续闪烁或背景漂移。`prefers-reduced-motion: reduce` 必须停用非必要动画和过渡，功能保持完整。

后续若需要更忠实的运动研究，仍按 P3 单独采集连续交互证据；本轮实现不把 P3 标记为完成。

## 可复用验证入口

[`scripts/check_ui.cjs`](../../scripts/check_ui.cjs) 从 SSR 预览二进制生成明确的样例数据页，在 Chromium 中检查布局。Playwright 与 Node 由运行环境提供，不作为应用运行依赖：

```sh
cargo build --features preview --bin preview
PLAYWRIGHT_MODULE=/path/to/playwright node scripts/check_ui.cjs
```

可选环境变量：`PREVIEW_BIN` 指定预览程序，`UI_CHECK_OUTPUT` 指定截图/JSON 目录，`CHROMIUM_PATH` 指定浏览器，`UI_CHECK_BROWSERS=chromium,webkit` 在安装了相应 Playwright 浏览器时增加 WebKit。默认输出位于系统临时目录 `whatoeat-ui-check`，不会把测试记录写进用户数据库。

检查范围包括八项原生主题选项、旧配色窄/宽屏、新界面的四页面与四种宽度、推荐状态、长列表、通知布局、固定导航（新界面也检查桌面）、可到达页脚、文字横向边界、菜单／记录页控件边界和减少动态效果。对可解析的不透明纯色控件背景检查文本对比度；渐变、半透明场景和装饰背景明确跳过，不将这项检查称为完整 WCAG 验收。保存代表截图与 `summary.json`；脚本以非零退出码报告失败。

SSR 没有 Dioxus 事件绑定，不能用这个脚本宣称吃/不吃、主题持久化、复制粘贴、通知计时器或原生设备交互已经端到端验证。这些由业务/组件测试、桌面构建和实际平台检查分别覆盖。当前已完成 94 个 Chromium 布局场景和 39 项 Rust 测试，平台边界与截图见[实现验收记录](implementation-validation.md)。
