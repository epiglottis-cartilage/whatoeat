# 架构：Dioxus + Rust + SQLite

状态：用户确认 Dioxus、方案 B、个人使用、本地优先、桌面及安卓。第一版各设备独立保存，支持复制粘贴合并，不实现同步。Linux 桌面已编译；安卓已用 JDK 26、SDK 37.0、NDK r30 构建 ARM64 调试 APK 并检查签名，尚未完成真机验收。本文件描述当前实现，替代早期 Tauri/Svelte/SQLx 草案。

## 调用方向

```text
Dioxus RSX / signals / CSS
    ↓ Command（Rust 枚举）
UI dispatch → spawn_blocking
    ↓
Store：SQLite BEGIN IMMEDIATE、命令去重
    ↓
Data：决策状态机、反馈、饮食历史
    ↓
Model：predict / update / replay
    ↓
SQLite：状态快照 + 请求回执
```

一个 Rust package 按模块组织。业务算法不依赖界面或操作系统；时间和抽样值从调用方传入。UI 通过普通 Rust 函数访问业务，不需要 Tauri IPC、HTTP 服务或单独的 TypeScript 前端。Dioxus 使用系统 WebView 绘制 HTML/CSS，业务原生执行，此实现没有 WASM 运行时。

数据库操作放到阻塞工作线程，界面等待期间禁用写按钮；只有成功提交后的状态才替换界面。失败后重新读取数据库，避免旧卡片继续操作。多窗口不会自动实时同步，但命令始终在写事务中读取最新状态。

## 模块

| 模块 | 职责 |
| --- | --- |
| `model.rs` | 两参数 logistic、梯度下降、先验正则、参考周期 |
| `domain.rs` | 单候选抽样、吃/不吃、历史变更、回放、备份校验 |
| `store.rs` | rusqlite + bundled SQLite、事务、回执、迁移/合并前备份 |
| `transfer.rs` | 无 ID 的交换格式、名称合并、记录及反馈去重 |
| `platform.rs` | 应用数据目录、桌面 WebView 剪贴板、安卓 JNI 剪贴板 |
| `ui.rs` | 推荐、历史、菜单、备份四个页面 |
| `main.rs` | desktop/mobile feature 入口 |

不提前拆 workspace、远程服务或同步引擎。后续可将 model/domain 抽为独立 crate，不改变模型语义。

## 持久化与一致性

饮食数据使用两张 SQLite 表：

- `app_state(id=1, payload)`：整个 `Data` 聚合的 JSON 快照。
- `command_receipts(request_id, command)`：命令标识与内容，用于幂等检查。

另有独立 `app_settings(key, value)` 表保存本机主题选择，不参与饮食记录的导出、合并或清空。主题通过页面根元素的 `data-theme` 和 CSS 变量应用到各页面、通知及导航。切换时立即预览，保存失败回退并显示通知；启动时与应用数据一起加载。

数据库设置 `user_version=3`、WAL、5 秒 busy timeout；拒绝高于当前的数据库版本。一个事务同时持久化反馈、食用记录、模型、下一张候选及请求回执。操作失败回滚，不会出现只记餐而未更新模型的半状态。同一请求标识配不同命令会报错；同一卡片重复提交相同回答也不会再记餐，即使原记录已撤销。

`Data` 保留单调修订号、菜单、食用事实、反馈事实和当前决策。移除了未使用的 `profile_id`、`session_id`；反馈直接使用对应推荐卡的 ID，不再同时保存两套事件标识。菜单/餐次 ID 用于改名和修改后的稳定引用，反馈 ID 用于撤销与重复点击校验，请求 ID 用于事务幂等，这些内部标识保留。删除记录采用软删除，模型是可重建的派生状态。

打开 v1/v2 数据库时，在事务中自动转换 JSON 快照，更新旧餐次的反馈引用，食用时间下取整到分钟并合并同名同分钟的记录，重建模型后升级到 v3。转换前把原始 JSON 刷盘保存到 `recovery/before-upgrade-*.json`；迁移失败回滚，原数据库不受影响。旧应用拒绝打开 v3 数据库，避免误写新格式。

菜单改名保留 UUID、历史与学习参数。删除菜单项会软删除并停用，保留历史引用和反馈；它不再参与推荐和新餐次选择，已有餐次仍可编辑。再次添加同名选项会获得新的 UUID 和初始模型。旧档案缺少菜单项的 `deleted` 字段时按未删除读取；500 项限制包含软删除项。

选择快照存储是为了先验证算法和交互，**不是已经实现了按实体规范化的关系表**。它的代价是每次操作读写整个档案，重建依赖历史扫描，命令回执也尚无清理策略。适合个人小规模实验，扩展到长期大量历史或多用户前需迁移实体表、索引及增量更新。备份限制 16 MiB、500 个菜单项、食用与反馈各最多 50,000 条；这是格式边界，不是性能承诺。

## 单候选状态机

```text
Idle → Ready → 接受 → Accepted
          └→ 拒绝 → 下一个 Ready / Exhausted
Accepted / Exhausted → 显式新一轮 → Ready
```

Ready 保存候选 UUID、展示时间、预测概率、抽样概率、上次食用时间与本轮已拒绝集合。重绘与重开保留同一卡片；卡片超过两小时后要求重新开始，未回答不构成负反馈。全部拒绝后显示结束状态，不在本轮无限重复。

点「吃」在同一事务中记录正反馈、写入当前食用记录并重建模型；「不吃」学习负反馈并排除本轮该项。无上次食用时间时使用 0.5 探索分数，但不训练时间曲线。补录是食用事实，不额外伪造接受反馈。

撤销会删除对应餐次并撤销其正反馈。编辑由推荐生成的餐次时撤销原接受样本，改为手动食用事实。按展示时间、回答时间和回答结果排序后回放，以更正后的历史重新计算每次反馈之前的最近食用时间；某条接受反馈绝不能把它自己产生的餐次作为学习起点。其他受影响的后续样本也随之重算。

## 复制、合并和平台

面向用户的交换格式为 v3 JSON（兼容 v2 导入）：`menu` 以名称描述启用/删除状态；`records` 保存名称与食用时间，来自推荐的记录附带展示时间和回答时间，反馈事件保留原有精度以避免截断餐次时间后错误学习未来事件；`rejected` 保存名称、展示时间和拒绝时间。不导出 UUID、模型参数、当前页面或抽样概率。导入先校验完整内容，再按名称映射到本地实体，最终清除候选并重算模型。旧版完整快照也可以粘贴导入。

名称比较会去首尾空格并转小写，不做模糊匹配。默认采用增量覆盖：同名菜单的名称、启用和删除状态以导入内容为准，未出现的本地选项保留。餐次以规范化名称和食用分钟匹配；同分钟以导入记录（含是否来自推荐）覆盖，本地其他分钟的餐次保留。一次导入内有重复键时最后一条生效。拒绝反馈仍以名称、展示时间、回答时间去重。重复导入不增加训练次数。覆盖餐次时撤销旧接受反馈，复用或建立新反馈，再统一重算模型。导入可以恢复同位置的本地删除或撤销记录，符合导入优先的规则。名字被改成不同名称后，跨设备按两个不同选项处理。

合并在副本上完成并验证容量，再在数据库事务中提交；出错不留下半份数据。合并前把原数据刷盘保存到 `recovery/before-import-*.json`。内部 `Restore` 和完整快照仅用于恢复与测试，导入界面只提供合并。此功能不会因导入缺少某条记录就删除它；只覆盖明确提供的同键内容。

桌面点「复制当前记录」通过 WebView 剪贴板写入；失败时显示可手工复制的文本。安卓通过 JNI `ClipboardManager` 写入。导入使用普通文本框粘贴和一次合并操作，无文件选择器和系统分享流程。默认数据在桌面系统应用目录；安卓在应用私有目录。`WHATOEAT_DATA_DIR` 可用于隔离测试。安卓剪贴板、首次安装、生命周期、键盘、返回键与不同 WebView 的实际行为仍需真机验收。

「清空全部数据」通过 `Clear` 命令在同一个事务中置空菜单、餐次、反馈和当前候选，删除旧请求回执，仅保留本次清空的幂等回执。页面提供确认和取消；清空后可直接重新添加菜单。数据库外已有的恢复副本不会随此操作删除。

## 验证

`tests/flows.rs` 覆盖两参数更新方向、合成反馈改善预测、冷启动、拒绝不重复、撤销及编辑回放、卡片过期、备份校验、事务恢复、进程重开和并发重复接受。`tests/transfer.rs` 覆盖无 ID 导出、跨档案同名合并、时间去重、重复导入、覆盖接受反馈、分钟精度、清空后重用、顺序无关的反馈重放、失败原子性与旧数据库迁移。静态预览复用实际 RSX，检查桌面及手机宽度；不会执行真实交互或写入演示数据。

其他平台与发布签名仍属于后续验证范围。安卓安装步骤见 [Android 开发说明](android.md)。
